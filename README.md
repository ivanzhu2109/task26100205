# VeloCache — 单向去重传输库

VeloCache 在分支网关场景下减少 WAN 流量：发送端用短引用代替接收端可能已缓存的
块内容；当两端缓存状态不一致（引用对应的块已被淘汰）时，协议自动补全，传输仍能
完整、正确地完成。两端只通过字节消息交互，各自使用私有本地目录，互不读取对方
状态。

## 特性

- 按 8 KiB 切块（末块可不足），仅逐字节相同的块可复用（SHA-256 标识）。
- 接收端可复用缓存固定 1 MiB，按原文字节计量，LRU 淘汰，内容存本地文件；
  会话状态在内存。同一块在一份传输中首次参与还原才算一次使用，重复消息不刷新。
- 引用未命中时接收端自动发送补全请求，发送端从本地暂存的原文取块补发，
  无需调用方重新提交；确认完成（ACK）后发送端立即释放原文。
- 消息可乱序、重复、任意延迟；结果按编号只交付一次，迟到消息不会重新交付
  结果或让已完成传输重新等待。
- 支持 32 份并发传输，每份最大 4 MiB；单线程驱动。

## 使用

```go
s, _ := velocache.NewSender("/path/sender-dir")   // 发送端私有目录
r, _ := velocache.NewReceiver("/path/receiver-dir") // 接收端私有目录（缓存存于此）

// 发送端：提交传输（id 唯一，data ≤ 4 MiB，在飞 ≤ 32 份）
err := s.Submit("transfer-1", data)

// 四类操作：
out := s.Pending()      // 取出待发送消息（发送端 -> 网络）
_ = r.Deliver(msg)      // 交付收到的消息（网络 -> 接收端）
back := r.Pending()     // 取出待发送消息（接收端 -> 网络）
_ = s.Deliver(msg)      // 交付收到的消息（网络 -> 发送端）
results := r.TakeResults() // 取回完成结果：[]Result{ID, Data}，每个 ID 只交付一次
```

调用方负责在本机把 `Pending()` 取出的字节消息投递给对端的 `Deliver()`；
消息保证最终送达（允许乱序、有限重复、任意延迟）。库本身不启动任何网络
或监听端口。`TakeResults()` 取走的结果不再被保留或用作缓存。

## 协议消息

| 类型 | 方向 | 说明 |
|------|------|------|
| Data | S→R | 携带块原文（8 KiB 或末块），含块哈希与总块数 |
| Ref  | S→R | 短引用：仅块哈希 + 序号（约 50 字节） |
| Need | R→S | 引用未命中，按块序号请求补全（每块只请求一次） |
| Ack  | R→S | 传输完整还原，发送端据此释放原文 |

发送端对首次出现的块发 Data，之后发 Ref；接收端命中缓存则直接使用，
未命中则通过 Need 请求补全。所有消息均为紧凑二进制编码。

## 测试

```sh
go test ./...
```

覆盖：预热后 100 次相同 1 MiB 传输的实际字节量（双向 ≤ 原文总量 5%，
控制消息计入）；引用生成后块被淘汰、引用随后到达时的自动补全（期间其他
传输正常完成）；数据与控制消息乱序、重复，以及原文释放后再次投递旧消息。
每个场景均逐字节核对结果、确认每个编号只交付一次、最终无悬挂传输。
